# 演示视频脚本（5–8 分钟）

> 要求：MP4、≥1080p、普通话、5–8 分钟。
> 录制前先把 `python tools/mock_server.py` 关掉，用真后端 `python run.py`，
> 并预先入库好演示论文（否则现场等解析会浪费时长）。

## 0:00–0:35 · 开场：把问题摆出来

**画面**：README 首屏，滚动到「这个项目解决什么问题」。

**旁白**：
> 通用大模型在科研场景里最危险的不是答得不好，而是答得像真的。
> 论文里写的是 8 张 P100、12 小时、28.4 BLEU，模型可以随口说成 16 张 V100、7 天、41.0 BLEU，
> 读起来毫无破绽。
> 我们做的知微，目标不是让模型更会写，而是让它的每一句话都能点回原文。
> 做不到，就不许说。

## 0:35–1:30 · 文献库与语义级去重

**操作**：左栏拖入 `1706.03762v1.pdf`，等状态变成「已入库」；再拖入 `1706.03762v7.pdf`。

**旁白**：
> 先看版本管理。这两个文件名字不同，但我们不看文件名，看正文指纹。
> 系统识别出这是同一篇论文的 v1 与 v7，依据是 arXiv 基号、标题和正文指纹三项吻合，
> 并给出「用新版本替换旧版本」的建议，同时列出 120 处章节级差异。
> 注意这里的判断是完全离线的语义比对，不是字符串匹配文件名。

**字幕**：`关系 = newer_version · 相似度 1.00 · 依据 = arxiv_base / title / content_hash`

## 1:30–2:20 · 版式感知阅读

**操作**：点开最新版，左栏目录逐级展开，点「5.2 Hardware and Schedule」跳到第 7 页；
正文里点 `[11]` 跳到参考文献，再点回来；点「翻译本页」看中英对照。

**旁白**：
> 解析层处理了双栏阅读顺序、标题树、9 张表格、3 张图、6 个公式和 40 条参考文献。
> 左边是自动还原的标题树，点一下直接定位。
> 正文里的引用标记和参考文献条目是双向无损跳转的。
> 翻译走的是学术翻译通道，公式和代码会被占位符保护起来，不会被翻坏。

## 2:20–3:40 · 抗幻觉问答（重点段）

**操作**：切到「问答」，输入「训练用了多少张什么型号的 GPU，训练了多久？」。
指着左侧时间线看 trace 事件逐条出现，右侧主张卡片逐张落下来。

**旁白**：
> 这个问题在真实科研里非常典型。请看右边——每一条主张都带一个裁决徽标。
> 前两条是「放行」，因为它们能从原文里逐字定位到，数字也逐一核对上了。
> 现在我再问一个原文里没有的问题。

**操作**：再问「作者有没有说这个架构可以替代卷积网络？」（构造一个会被拦下的）

**旁白**：
> 这条被拦下了。理由是引文在原文中定位不到。
> 请注意，这三道硬检查——有没有证据、引文能不能定位、数字一不一致——
> 全部是纯词法、离线、可复现的，模型绕不过去。
> 只有最后一道「证据是否足以支撑」才交给模型裁判。
> 判不了的情况，比如中文问题对英文原文，系统会明确标成「待核实」，
> 而不是假装判了个低分。

## 3:40–4:45 · Agent 调研（本赛项主命题）

**操作**：切到「调研」，输入「Transformer 这条线在解决什么问题，现在还有哪些没做完的方向？」。
先点「只看计划」展示 Agent 打算怎么做，再点「开始调研」，
指着左边时间线看每一步依次落下来，右侧看发现汇总，最后看下方过闸门后的答案。

**旁白**：
> 这一页是这次比赛的主题：Agent，而且它不是一段写死的流程。
> 先看「只看计划」——这份计划是模型照着工具名册现产的。
> 规则很硬：规划器不许发明工具，名册里没有的工具名会被直接丢掉。
> 现在开始调研。左边这条时间线上，每一步调了哪个工具、传了什么参数、花了多久、拿到了什么，
> 全部摊开给人看。它先盘点库情，再去检索证据，接着建引用图谱、挖核心节点、扫 Future Work；
> 中间会回过头看已有观察，判断还缺什么，最多再补两步。
> 工具捞到的证据会汇成一个证据池，最终答案收窄到最相关的那几篇文献上。
> 最后一件事最关键：收尾走的还是同一个问答引擎，逐句主张照旧要过主张闸门。
> Agent 新增的能力是「会去找」，不是「答案免检」。

**字幕**：`规划 → 调工具 → 记观察 → 再规划 → 收尾过闸门`

## 4:45–5:35 · 引用图谱与综述

**操作**：切到「图谱」，点「构建引用图谱」。指着节点大小和颜色，点一个基石节点看右侧详情。
勾选「只看实质引用」看边数变化。再切到「综述」生成，点「扫描 Future Work 时效性」。

**旁白**：
> 这是赛题里权重最高的一块。节点大小是 PageRank，颜色是角色。
> 每个角色都有一句人话理由，比如「中介中心性位居前 25%，连接不同引用簇」。
> 勾上「只看实质引用」——纯罗列的应付式引用会被剔除，边数从 26 降到 18。
> 综述是从图谱长出来的：先有骨架，再挑材料，最后逐句过闸门。
> Future Work 那一栏会去查后续工作，把已经被解决的旧 idea 标出来，
> 省得你去做别人做完的题。

## 5:35–6:15 · 写作与可视化

**操作**：切到「写作」，输入一句 idea，点「生成框架」；
点「用引用图谱生成」看 Mermaid 预览；粘贴一段 CSV 点「出图」。

**旁白**：
> 写作模块的参考文献不由模型写。模型只回答「这句话该引用库里第几篇」，
> 引用串由元数据拼装——所以库里没有的文献，物理上不可能被引用出来。
> 架构图支持 Mermaid、Graphviz、TikZ，CSV 直接出图并自动生成 Figure Caption。

## 6:15–6:55 · 阈值标定（差异化亮点）

**操作**：终端跑 `python evals/calibrate.py`，滚动到输出的对比两行。

**旁白**：
> 闸门的两个阈值不是拍脑袋定的。我们标了 39 条数据，
> 扫了阈值网格，默认的 0.35 / 0.75 拿到 0.916 的宏平均 F1，
> 标定后的 0.20 / 0.85 是 0.975。脚本不需要任何密钥就能复现。

## 6:55–7:25 · 收尾

**操作**：切回界面总览，或展示 `python tools/mock_server.py` 的无依赖启动。

**旁白**：
> 最后，整套系统可以在没有密钥、没有外网、甚至没有第三方向量库的环境里完整跑起来，
> 因为最关键的抗幻觉检查本来就是离线的。
> 科研助手不该写得像，而该指得出。这就是知微。

## 录制检查清单

- [ ] 分辨率 ≥ 1920×1080，浏览器缩放 100%
- [ ] 提前入库好两版论文，避免现场等待解析
- [ ] 提前跑一次「调研」预热（首次调用要建工具名册与图谱缓存，别在录制时等）

- [ ] 关闭通知与无关标签页
- [ ] 控制台不要出现红色报错（PDF 缺失的 `MissingPDFException` 属预期降级，可忽略）
- [ ] 普通话配音，语速适中，总时长落在 5–8 分钟
- [ ] 视频里不要出现任何 API Key
